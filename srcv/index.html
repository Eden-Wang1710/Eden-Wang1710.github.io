1Introduction

Large language model (LLM) agents can solve complex tasks by interacting with external tools to acquire evidence and perform multi-step reasoning. In legal reasoning, DeonticBench evaluates whether models can apply explicit rules to case-specific facts, while DAR extends this setting with agentic harnesses for accessing statutes and executing computations. The agent must examine a given statute, identify the applicable provisions, conditions, and exceptions, and reason about their implications for the case. In contrast, BrowseComp-Plus evaluates agents on complex questions that require searching a large collection of web documents and combining evidence from multiple sources. While the former emphasizes selecting and applying rules from a given document, the latter emphasizes discovering relevant evidence across a much larger search space.

Existing agent harnesses, such as Terminus-2 and KIRA, largely rely on a single agent to retrieve, reason, and answer. As the agent interacts with tools, its context accumulates search queries, retrieved documents, intermediate reasoning, and repeated tool outputs, making it difficult to maintain relevant evidence throughout long trajectories. Recent work, such as SelfCompact and Context Language Models, explores adaptive context management to address growing interaction histories. However, these approaches primarily manage information after it has entered the agent’s context, rather than controlling which information enters the main reasoning trajectory in the first place, which allows irrelevant evidence and redundant tool outputs to accumulate before compaction is triggered, potentially compromising the agent’s ability to manage its context effectively.

To address this limitation, we develop a Solver–Reader–Compaction–Verifier (SRCV) Harness that combines proactive and reactive context management. The reader proactively selects relevant evidence while keeping its intermediate retrieval process outside the solver’s main trajectory. The compaction module subsequently manages the accumulated context by preserving essential evidence and reasoning while removing redundant information. A rubrics-based verifier examines candidate answers against the source evidence and provides feedback for revision. The design is implemented at the harness level, allowing it to be integrated with different base agents.

2Method: SRCV (Solver–Reader–Compaction–Verifier) Harness

2.1Architecture Overview

We introduce SRCV, a harness that combines proactive evidence selection, reactive context compaction, and reasoning verification. Given a task x and an external evidence source D, SRCV organizes the agent’s workflow into four roles: Solver, Reader, Compaction, and Verifier. All four roles use the same underlying language model, with role-specific instructions and skills. The solver maintains the main reasoning trajectory, while the reader and compaction module operate on branches of its context. The verifier independently examines candidate answers against the source evidence. This separation allows harness to control the information entering the main agent’s context, manage its accumulated history, and provide feedback for answer revision.

2.2Proactive and Reactive Context Management

Solver. The solver is the main agent responsible for planning, tool calling, and reasoning to produce the final answer. The solver can request additional evidence from the reader through a query, or invoke compaction when its context becomes redundant or approaches the context limit.

Reader: Proactive Context Control. Rather than allowing the main agent to directly accumulate all retrieved documents, SRCV delegates evidence acquisition to a reader agent. In DeonticBench, the reader identifies applicable statutes, including relevant conditions and exceptions. In BrowseComp-Plus, it searches a large document collection for evidence relevant to the query.

In BrowseComp-Plus, we implement a selective reader as in Figure 2 that initially examines only the first 512 tokens of each retrieved document and assesses its relevance to the task. When further inspection is needed, the reader can selectively retrieve additional line ranges (OPEN) or search for specific phrases (FIND), with at most three additional actions per document. Only the selected source passages are forwarded verbatim to the solver, while the reader’s intermediate processing remains outside the solver’s context.

Compaction: Reactive Context Management. Although the reader limits full documents entering the main trajectory, the solver’s context continues to grow through multi-turn retrieved evidence and reasoning steps. SRCV therefore introduces a complementary compaction module that reorganizes the accumulated context. When invoked by the solver, the compaction agent identifies the task state, essential evidence, and intermediate results needed for subsequent process.

Prefix Caching. To reduce the inference overhead introduced by subagents, we leverage prefix KV-cache reuse. On DAR, the reader and compaction agents operate as branches of the solver’s context, sharing its existing prefix rather than recomputing the entire trajectory. On BrowseComp-Plus, successive selective reader actions reuse the cached prefix of the same reading session. This design reduces redundant prefill computation and mitigates the additional inference cost of SRCV.

2.3Self-Verification

Verifier: Rubrics-Grounded Verification. Before finalizing an answer, SRCV invokes a verifier to examine the solver’s candidate answer against the source evidence. Using three complementary rubrics, the verifier assesses evidence coverage, alignment between the evidence and task, and the logical consistency of the reasoning and final answer. The feedback identifies potentially missing evidence or unsupported reasoning and allows the solver to revise its answer.

3Experiments

3.1Setting

Models. We evaluate SRCV using two open-weight language models: Qwen3.5-35B-A3B for DAR and Qwen3.5-9B for BrowseComp-Plus. All models are served locally using vLLM 0.20.1 on an NVIDIA DGX Spark. For DAR, we use BF16 precision, a 65k-token model context window, and a maximum of 16k generated tokens per turn, with a 32k-token compaction threshold. We enable thinking mode and use temperature 0.7, top-p 0.95, and top-k 20. For BrowseComp-Plus, we follow the CLM-Agent setup with a 28k-token context budget and a maximum of 100 agent steps.

Base Harnesses. On DAR, we evaluate SRCV with two base harnesses: Terminus-2 and Terminus-KIRA. Terminus-2 uses shell-based tool execution, while KIRA extends it with native tool calling. We compare SRCV against their original implementations under the DAR evaluation framework. On BrowseComp-Plus, we build upon the released CLM-Agent, which uses a Mini-SWE-Agent-based execution loop and allows the model to edit its accumulated context. SRCV extends these base harnesses with dedicated reader and verifier roles, while retaining their underlying agent execution mechanisms.

Benchmarks. We evaluate SRCV on two complementary benchmarks. For deontic reasoning, we use the SARA hard split of DeonticBench. SARA-Numeric contains 35 cases requiring numerical tax calculations, while SARA-Binary contains 30 cases requiring Entailment or Contradiction judgments. For large-scale information retrieval, we use BrowseComp-Plus, which consists of 830 challenging questions over a fixed corpus of approximately 100k web documents. Our preliminary evaluation uses a fixed 50-question subset. We use Qwen3-Embedding-8B with the released retrieval index to retrieve the top 10 documents per search.

Evaluation Protocol. We report exact-match accuracy for SARA-Numeric and macro-F1 for SARA-Binary. For BrowseComp-Plus, we evaluate answer correctness using Qwen3.5-35B-A3B as a judge with temperature 0, following the benchmark’s grading template. Missing answers are counted as incorrect. Alongside task performance, we measure inference cost to characterize the accuracy–cost trade-off. For DAR, we estimate cost from token usage using a fixed pricing scheme. For BrowseComp-Plus, we report average PFLOPs per question, accounting for prefix KV-cache reuse by counting shared prompt prefixes only once per trial.

First, filtering retrieved documents before they enter the solver’s context reduces context accumulation. As shown in Table 3, 32 of the 36 unsuccessful CLM-Agent trials terminated after exhausting context-limit recovery attempts, compared with none under SRCV. Second, reader-mediated retrieval enables broader document exploration under a fixed context budget. As shown in Table 4, SRCV examines 2.28 times as many documents per question while reducing the solver’s context load per search result by 87.8%.

However, these improvements come with additional inference cost, motivating further improvement of cost efficiency.

5Challenges and Next Steps

Inference Cost. Although SRCV improves answer accuracy, its additional agent calls introduce substantial computational overhead. We plan to investigate more efficient KV-cache reuse and adaptive stopping strategies, inspired by agentic abstention, to reduce unnecessary tool calls and improve the accuracy–cost trade-off.

Confidence Estimation. We further aim to estimate answer reliability from the verifier’s assessments. However, preliminary experiments show that both self-verbalized confidence and verifier rubric scores poorly distinguish correct from incorrect answers. We plan to explore representation-based confidence estimation using the verifier’s hidden states.
